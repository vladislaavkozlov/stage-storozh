# Сторож прода Wellstage

Раз в минуту проверяет `https://app.wellstage.ru/health` и онлайн-запись заведений (страница, её скрипт, данные заведения, специалисты). Список заведений - `ZAVEDENIYA` в `storozh.mjs`.

Что приходит в Telegram:
- 🔴 / 🟠 - прод или запись заведения не работают две минуты подряд, и это подтверждено: сервер ответил ошибкой или не открылся и из России. В тревоге ссылка на запись Карины - видно клинику и врачей, значит всё работает. Про запись - только когда сам прод отвечает
- ⚪️ «не может проверить» - из США не открывается 10 минут, а из России проверить не удалось ни одним сервисом. Это не тревога: сторож не знает, падение это или обрыв связи, и просит открыть ссылку самому
- напоминание раз в 30 минут, пока не работает, и ✅ после двух удачных проверок подряд - с длительностью простоя
- ⚪️ - сам сторож не работал дольше 10 минут (сбой GitHub) и прод в это время не проверялся
- 📊 сводка за прошедшие сутки после 9:00 МСК: простои, доступность, скорость ответа, перезапуски сервера, число коротких обрывов связи. Нет сводки к 10 утра - сторож не работает

Вторая точка в России: сторож живёт на GitHub в США, и связь до Москвы рвётся сама по себе. Когда до сервера не достучались вовсе, сторож одновременно спрашивает два бесплатных сервиса без ключа: Globalping (три случайные точки в России у разных провайдеров) и check-host.net (узлы в Москве). Открылся хоть с одной точки - тревога ложная, сигнала нет, она считается и приходит числом в сводке. Без ответа из России красной тревоги нет (07.11.2026: check-host перестал отвечать, и сторож поднял ложную тревогу).

Работает на GitHub Actions, вне Amvera. Ключ бота и чат - в секретах репозитория `TG_TOKEN` и `TG_CHAT_ID`.

Проверить вручную: вкладка Actions → storozh-proda → Run workflow с галочкой «проверка» - придёт состояние сейчас и счётчики за сегодня.
